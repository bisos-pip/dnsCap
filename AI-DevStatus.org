* Key Design Decisions

  - =DnsSpecMethod= enum gates which backend manages =/etc/hosts= entries; currently
    only =etcHosts= is pursued. =tinydns= is a placeholder for later.
  - =dnsCap_update= calls =sudo -E PATH=<user-PATH> <python> <py-dblock.cs>= directly
    rather than going through =bannaInfo.cs -i updateEtcHosts=. This is necessary
    because =sudo= strips PATH, so both =py-dblock.cs= and the commands it shells out
    to (e.g. =bannaInfo.cs=) must be reachable. =sudo -E= with an explicit =PATH==
    preserves the calling user's venv PATH for all subprocesses.
  - =shutil.which= is used at runtime to resolve =py-dblock.cs= to an absolute path
    before passing it to =sudo=, since =sudo= won't find scripts in the venv bin dir
    by name alone.
  - The =.pcs= file sets both =fqdn= and =dnsSpecMethod= on =cntrlInfo= before
    declaring the =csCmndsList= — this is the standard dnsCap usage pattern.
  - =examples_csu= must be a plain =@cs.track def= function (not a =cs.Cmnd= class)
    to avoid a framework =perfName= AttributeError when invoked via =dnsCap_seed.cs -i examples_csu=.
