* Overview

/bisos.dnsCap/ provides DNS management facilities that contribute to BISOS
*Capabilities*. In BISOS, a *Capability* is a specific concept, specified and
realized through /bisos.capability/. =dnsCap= is not itself a Capability; it is
one ingredient — the DNS aspect — of a full *CBS* (Capability Bundle
Specification), alongside sibling aspects such as =webCap= and =sbom=.

Concretely, =dnsCap= supplies the DNS naming an application needs. Its first
backend maintains =/etc/hosts= entries for the =.here= domain (e.g.
=airflow.here=), using the =bisos.banna= dblock machinery to keep those
entries in sync.

=dnsCap_seed.cs= is a seed. Common usages take the form of a
=<name>-here-dns.pcs= plant that names the fqdn to manage.

dnsCap also holds BISOS's DNS servers, as bedrock capabilities (decided 2026-10-10,
bisos-pip/pals/palsWithBcm README.org 1.2): *Knot DNS* as the authoritative server, driven
tinydns-style from generated zone files, and *Unbound* as each platform's local resolver,
sending =.intra= to Knot. =.here= stays in =/etc/hosts=: its names are loopback addresses,
meaningful only on the platform itself. See [[#knot-dns-and-unbound][Knot DNS and Unbound]].

* Relation to BISOS Capabilities

A BISOS *Capability* is specified and realized by /bisos.capability/ as a
*CBS* (Capability Bundle Specification) — a bundle of component aspects.
=dnsCap= is the DNS aspect of that bundle. Its sibling aspects include:

- =dnsCap= — DNS naming (this package): =/etc/hosts= and, later, other DNS backends.
- =webCap= — the web-service aspect.
- =sbom= — the Software Bill Of Materials aspect (typically a =*-sbom.pcs= plant).

A CBS composes these aspects into the complete specification of a Capability.
=dnsCap= can be used on its own (as shown below) or as an ingredient invoked
from within a CBS. For the Capability concept itself, see
[[https://github.com/bisos-pip/capability][bisos.capability]].

* Part of BISOS — ByStar Internet Services Operating System

Layered on top of Debian, *BISOS* (By* Internet Services Operating System)
is a unified and universal framework for developing both internet services and
software-service continuums that use internet services. See
[[https://github.com/bxGenesis/start][Bootstrapping ByStar, BISOS and Blee]]
for information about getting started with BISOS.

*BISOS* is a foundation for *The Libre-Halaal ByStar Digital Ecosystem* which
is described as a cure for losses of autonomy and privacy in a book titled:
[[https://github.com/bxplpc/120033][Nature of Polyexistentials]]

/bisos.dnsCap/ is part of BISOS. It is a standalone package that can
be used independently of the full BISOS environment.

* bisos.dnsCap is a Command-Only PyCS Facility

bisos.dnsCap is a command-line tool. It is a PyCS single-unit
command service. PyCS is a framework that converges development of CLI tools
and services. PyCS is an alternative to FastAPI, Typer and Click.

bisos.dnsCap uses the PyCS-Framework to provide the DNS aspect of a BISOS
Capability:

1) Update =/etc/hosts= with the DNS entries for a =.here= fqdn (via the
   =bisos.banna= dblock machinery).
2) Verify that =/etc/hosts= contains the expected banna dblock markers.
3) Resolve and ping a managed fqdn to confirm the entry is in effect.

The core of PyCS-Framework is the /bisos.b/ package (the PyCS-Foundation).
See [[https://github.com/bisos-pip/b][bisos.b]] for an overview.

* Usage

** Example: managing airflow.here in /etc/hosts

A plant such as =airflow-here-dns.pcs= names the fqdn and the DNS backend:

#+begin_src python
from bisos.dnsCap import dnsCap_seedInfo
cntrlInfo = dnsCap_seedInfo.cmndsControlInfo
cntrlInfo.dnsSpecMethod = dnsCap_seedInfo.DnsSpecMethod.etcHosts
cntrlInfo.fqdn = "airflow.here"
#+end_src

With that plant in place, the full cycle is:

#+begin_src bash
# Rewrite /etc/hosts (backs up to /etc/hosts.<dateTag> first; runs under sudo)
bin/airflow-here-dns.pcs -i dnsCap_update

# Confirm the banna dblock BEGIN/END markers are present in /etc/hosts
bin/airflow-here-dns.pcs -i dnsCap_verify

# Resolve and ping the managed fqdn
bin/airflow-here-dns.pcs -i dnsCap_resolve  airflow.here
bin/airflow-here-dns.pcs -i dnsCap_fqdnPing airflow.here
#+end_src

After =dnsCap_update=, =/etc/hosts= contains a banna-generated block, e.g.:

#+begin_src text
####+BEGIN: bx:dblock:global:run-result-stdout :command "bannaInfo.cs -i bannaForEtcHosts"
127.0.22.100  airflow.here  # port=24006
...
####+END:
#+end_src

and =ping airflow.here= then resolves to =127.0.22.100=.

** Commands

| Command           | What it does                                                    |
|-------------------+-----------------------------------------------------------------|
| =dnsCap_update=   | Safe-copy =/etc/hosts=, then rewrite its banna dblock (sudo).   |
| =dnsCap_verify=   | Check that =/etc/hosts= has the banna dblock BEGIN/END markers. |
| =dnsCap_resolve=  | Resolve the fqdn via =getent hosts=.                            |
| =dnsCap_fqdnPing= | Ping the fqdn once to confirm the entry is in effect.           |

* Knot DNS and Unbound

Both are built but not yet run on a host; testing is on another machine. Design and open
items: =AI-WorkPlan.org= Stage 4 (=<<knotStartingPoint>>=, =<<unboundStartingPoint>>=).

| Names              | Scope         | Resolved by                                             |
|--------------------+---------------+---------------------------------------------------------|
| =.here=            | this platform | =/etc/hosts= (=dnsCap_update=, above)                   |
| =.intra=           | this site     | Unbound -> stub zone -> Knot (=127.0.53.1@53=)          |
| everything else    | the world     | Unbound, full recursion with DNSSEC validation          |

** Knot DNS --- authoritative, tinydns-style

BISOS data is the single source. dnsCap generates plain zone files and =knot.conf=,
validates them (=kzonecheck=, =knotc conf-check=), installs them only when changed --- an
unchanged zone keeps its SOA serial --- and publishes with =knotc zone-reload=. The server
keeps no state of its own (=zonefile-load: whole=, =journal-content: none=,
=zonefile-sync: -1=). Zones: =here.= (from banna, for testing only) and =intra.= (SOA/NS so
far). Debian's =knot.service= is used as is.

#+begin_src bash
knot-sbom.pcs -i sbom_fullUpdate          # knot, knot-dnssecutils, knot-dnsutils; then publish
knotDns.cs -i knotZoneStdout here         # a zone as it would be generated (writes nothing)
knotDns.cs -i knotFullUpdate              # zones, then knot.conf
knotDns.cs -i knotQuery kafka.here        # kdig @127.0.53.1
#+end_src

** Unbound --- the platform's local resolver

Full recursion by default (no ISP resolver log), DNSSEC validation, QNAME minimisation; a
=forwardTls= mode forwards over DNS-over-TLS instead. Company/VPN domains are forwarded to
their connection's own DNS servers by a NetworkManager dispatcher. Firefox and
Chrome/Chromium policies turn their DNS-over-HTTPS off, so they use this resolver.
=/etc/resolv.conf= is switched only after Unbound answers; =resolverRevert= undoes it.

#+begin_src bash
unbound-sbom.pcs -i sbom_fullUpdate       # unbound; then conf, switch, browser policies
unboundDns.cs -i unboundConfStdout        # bisos.conf as it would be generated
unboundDns.cs -i unboundQuery debian.org  # kdig @127.0.0.1
unboundDns.cs -i resolverRevert           # restore the original resolv.conf
#+end_src

Known trade-off: with its DoH off, Firefox does not use Encrypted Client Hello. A local DoH
endpoint on Unbound (needs the platform CA, palsWithBcm 1.4) is the planned fix.

* Key Files

- =py3/bin/dnsCap_seed.cs= — the seed entry point.
- =py3/bin/airflow-here-dns.pcs= — example plant for =airflow.here=.
- =py3/bin/exmpl-here-dns.pcs= — example plant for =exmpl.here=.

- =py3/bisos/dnsCap/dnsCap_seedInfo.py= — =DnsSpecMethod= enum (=etcHosts=,
  =tinydns=) and the =fqdn= / =dnsSpecMethod= control info.
- =py3/bisos/dnsCap/knotInfo.py=, =knot_csu.py=, =py3/bin/knotDns.cs= — Knot DNS: facts and
  generators, Cmnds, entry point. =knot-sbom.pcs=, =knot-cbs.pcs=, =cbmProc-knot.spcs= —
  its sbom, bedrock CBS and CBM leaf (=collective/bedrock/knot=).
- =py3/bisos/dnsCap/unboundInfo.py=, =unbound_csu.py=, =py3/bin/unboundDns.cs= — Unbound,
  likewise; =unbound-sbom.pcs=, =unbound-cbs.pcs=, =cbmProc-unbound.spcs=.
